## 0. 30 秒电梯陈述（必须背熟）

> 在 openGauss 开源适配（B 兼容 + Dolphin MySQL 协议 + Peewee）过程中，配置点分散、新手难查准，我做了纯 RAG 的配置问答助手 **opengauss-rag**。主链路手写：Markdown 标题切片 → SiliconFlow bge-m3 嵌入 → Chroma → **BM25 + 向量加权 RRF**（配置项偏词法）→ 检索层低相关**代码拒答** → DeepSeek 生成并强制 `[n]` 引用 → FastAPI `POST /ask`。离线评测对比了纯向量与混合检索，并记录 badcase 驱动迭代。

**被追问时立刻补一句：**  
「评测是自建小样本（来源题 + 越界题），指标是检索 Recall 和拒答是否触发，不是线上准确率。」

## 3. 逐模块深挖题

### 3.1 切片（chunker2）

| 问题 | 参考答法 |
|------|----------|
| 为什么标题优先？ | Markdown 标题对齐「配置主题」，切出来的块语义完整，`heading_path` 便于引用溯源。 |
| 为何 1200 字符 / 120 重叠？ | 约对应数百 token，给 embedding 与 Prompt 一个折中；重叠减轻边界截断。**有消融**：400/800/1200/1600 在关键词 Recall 上打平，故保留 1200；并说明该指标偏松，不能证明对生成质量无影响。 |
| 切片太碎会怎样？ | 上下文碎、检索「碰到关键词」但答不全；太长则噪声多、引用粒度粗。 |

### 3.2 嵌入与向量库

| 问题 | 参考答法 |
|------|----------|
| 模型是谁？为何 API 不本地 bge-small？ | SiliconFlow `BAAI/bge-m3`；工程先跑通闭环，本地小模型可后续替换，接口已抽象在 `embed_client1`。 |
| 为何 Chroma？ | 本地 PersistentClient，无服务依赖，适合个人项目与可复现实验。 |
| 距离度量？ | 显式 `hnsw:space = cosine`。 |
| 为何 embed 有重试？ | 实测偶发 SSLError/ReadTimeout，评测中途会断；退避重试保证脚本可跑完。 |

### 3.3 混合检索（核心，必问）

| 问题 | 参考答法 |
|------|----------|
| 为何要混合？ | 标识符配置项（如 `enable_dolphin_proto`）向量易被语义相近段冲淡，需要 BM25；纯自然语言又需要向量。badcase：纯向量下该配置项 Top1 曾错，混合后回到正确段。 |
| RRF 是什么？ | 不比两路绝对分，只比排名：`score += w / (60 + rank)`。 |
| 加权策略？ | 查询含 snake_case 标识符 → 词法权重更高（如 0.45 向量 / 0.55 BM25）；否则语义更高（约 0.75 / 0.25）。 |
| 标识符提权？ | 文档正文命中查询中的标识符时，RRF 分 **+0.02** 量级微调，避免盖过主排序。 |
| 中文 BM25 怎么分词？ | 手写轻量 tokenizer：英文/标识符整词 + snake_case 子词 + 中文单字；单字对中文是弱基线，但在配置 token 场景够用，且与向量互补。 |
| 已知缺陷？ | 短标题块有时排位偏前；RRF 偏好双路共识，单路冠军可能掉名次 → badcase 里用加权缓解。 |

### 3.4 拒答与防幻觉（核心，必问）

| 问题 | 参考答法 |
|------|----------|
| 只靠 Prompt 行不行？ | 不行，服从性不稳定；必须在**调用 LLM 之前**代码层拒答。 |
| 当前规则？ | `no_hits` 或 `max(bm25_raw) < 2.0` 或 `min(vector_distance) > 0.52`（OR）。 |
| 为何 OR 不是 AND？ | 评测发现：中文长文档下库外题 BM25 会虚高（天气 top bm25 可到 13+），AND 会漏拒；OR 保证「词法极弱或语义很远」任一成立就拒。 |
| 阈值怎么定的？ | `peek_signals` + `eval8` 小样本标定。扩语料到 120 后：库内 top 距离约 0.27～0.36，库外约 0.53～0.68，GIL 在 0.55 阈值下漏拒，故收紧为 **0.52**。语料再变必须重标。 |
| Prompt 侧约束？ | 只依据资料；结论标 `[n]`；不足则说「根据现有文档无法确认」；简洁中文。 |
| 引用怎么校验？ | 正则解析 `[n]`，检查是否越界；拒答路径强制 `cited=[]`；响应含 `citation_valid` / `invalid_citations`。 |
| 拒答时还返回 contexts 吗？ | 返回，便于观测检索到了什么，但 `refused=true`，且不调用模型。 |

### 3.5 生成与 Prompt

| 问题 | 参考答法 |
|------|----------|
| 模型与参数？ | DeepSeek `deepseek-chat`，`temperature=0.2`，非流式，手写 `requests`。 |
| 为何低温？ | 配置问答要严谨，降低编造与发散。 |
| 资料如何编号？ | 用户 Prompt 中 `[i] 来源 | 小节 + 正文`，与返回 `contexts` 顺序一致。 |
| 为何有时答案写「无法确认具体取值」？ | 语料只覆盖「作用/配错后果」时，模型被要求不编造 on/off、默认值等；这是预期行为，不是缺陷。 |

### 3.6 FastAPI

| 问题 | 参考答法 |
|------|----------|
| 接口？ | `GET /health`、`POST /ask`，Body `{query, k}`，响应含 answer/refused/cited/contexts。 |
| 为何检索器单例？ | HybridRetriever 会全量建 BM25；每请求新建浪费时间内存；进程内懒加载复用，并注入 `answer(..., hr=...)`。 |
| 为何本地 smoke 用 `trust_env=False`？ | 系统代理会劫持 `127.0.0.1`，导致 502/空 body；忽略环境代理访问本机服务。 |
| 错误处理？ | 缺 API Key / LLM HTTP 失败 → 500；Pydantic 校验空 query → 422。 |

### 3.7 离线评测（必问，数字要准）

| 问题 | 参考答法 |
|------|----------|
| 测什么？ | ① 来源题 8 道：纯向量 vs 混合 Recall@1/@3；② 越界题 4 道：代码层拒答是否触发；③ 切片消融。 |
| 为何评测不调 LLM？ | 把「检索质量」「拒答」与「生成质量」解耦，成本低、可重复；生成侧目前靠人工看 answer + 引用。 |
| 真实数字（扩语料后）？ | 向量 R@1=87.5%、R@3=100%；混合 R@1/R@3=100%；OOS 拒答 4/4（100%）。向量失败例为 S6 认证异常类问题。 |
| Recall 如何算？ | Top-k 文本或 `heading_path` 命中任一关键词即命中——**口径偏松**。 |
| 指标局限？ | 无答案正确率/幻觉率自动标注；小样本；关键词不能代表生成质量；不能外推生产。 |
| 迭代故事？ | ① 纯向量标识符冲淡 → 混合+加权 RRF；② 混合曾让语义题回归 → 无标识符加大向量权重；③ 扩语料后 OOS 75% → DIST_MIN 0.55→0.52 回到 100%。 |

## 6. 高频技术追问与答法（题库）

1. **RRF 和加权求和融合的区别？** — RRF 比排名不比绝对分，避免向量距离与 BM25 分数量纲不可比；加权在 RRF 内体现通道偏好。  
2. **为何标识符要提权 BM25？** — 配置项是精确 token，词法信号更可靠。  
3. **如何降低幻觉？** — 检索质量 + 检索层拒答 + Prompt 约束 + 引用校验 + 低温；评测盯越界题拒答。  
4. **Recall@3=100% 为何还说不够？** — 关键词命中≠答案正确；样本小；仍需生成侧评测。  
5. **语料为何不全用官方文档？** — 当前用实习笔记/速查保证可复现个人故事；官方文档是后续扩展，会改变检索分布与阈值。  
6. **BM25 中文为何用单字？** — 实现简单、无分词依赖，标识符用完整 token；更优可用 jieba/专业分词，属后续优化。  
7. **chroma 数据为何不进 Git？** — 体积与可重建性；`.gitignore` 忽略向量库与 `.env`。  
8. **API Key 如何管理？** — `.env` 本地，仓库只有 `.env.example`；绝不提交真实 Key。  
9. **并发/性能？** — 未做压测；单例检索器避免重复建索引；个人 demo 以正确性与可讲性优先。  
10. **下一步若只做三件事？** — ① 扩充官方文档语料并重标阈值；② 生成质量/幻觉标注评测；③ 可选 cross-encoder 重排。
